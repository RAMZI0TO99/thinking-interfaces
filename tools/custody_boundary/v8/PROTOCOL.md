# V8 inventory observation protocol

The governing scoped contract is
[the inventory addendum](../../../docs/phase2/cho51_p3_inventory_contract_20261029.md).
Root authors this protocol, the addendum and admission orchestration. The
inventory implementation author owns inventory.py, test_inventory.py,
child_entry.py and validation_runner.py. Different agents review source and
actual results. No admission exists merely because this file exists.

The two modes are `tests` and `inventory`, each with a fresh UUID, create-once
attempt, exact source/runtime maps, independently accepted review digest,
explicit Root adoption, local stop and finite admission. The runner's REQUIRED
list is the closed source set. Runtime pins enumerate the known base Python
files, excluding site-packages; the resulting claim is only that exact roster.
No imported-image or installation-completeness claim is permitted.

Before either admission, Root creates contract-adoption.json binding the exact
contract and independent source-review hashes, with scoped-inventory status
and all authority fields false. Each admission pins that record; the runner
retains it and checks its exact fields, hashes and pre-admission UTC ordering.

Resource limits are4GiB startup/active RAM,20GiB disk,512/768MiB process/Job,
45s child,75s work,90s whole runner,1MiB result, one library worker, hidden GPUs.
This new lightweight envelope is justified in the addendum. It does not change
the limits of another phase. Stop presence/uncertainty and a failed guard stop
owned work; unrelated processes and caches remain outside the operation.

Inventory files and ancestor identities remain retained from byte observation
through probe completion, final verification and publication. Inputs exclude
ordinary incompatible writers/deletion. Outputs use parent-owned create-new
original handles with flush/read-back checks and exclusion of other writers.
The inventory child produces no artifact or inventory assertion. Its observed
exit/empty Job/original handle closure proves only the new owned lifecycle.
If no streams are used, acceptance must not invent stream-EOF evidence.

Tests are nonnumerical, using injected failures and any actual filesystem
fixtures only under the fresh admitted test attempt. Source review must cover
writer conflicts, path/link/size/scope bounds, output collision/read-back,
immutable identity/retention and failure cleanup, plus inherited Job controls.
Runtime tests do not qualify a historical host or a later operation.
The test child alone writes a bounded test-report.json beside its own fixtures;
the parent retains it and requires exactly19 tests, zero failures/errors/skips,
strict types and false authority fields. Inventory mode has no child report.

Each actual tool result, before/after UTC/QPC and immutable saved receipt is
retained. A different actual reviewer must check all joins and limitations;
Root then rechecks pins and records adoption. Pending flags in child/runner
receipts are never rewritten. Failure consumes the UUID. No automatic retry.

Historical cleanup/release/retry, current-boundary qualification, launch and
scientific authority remain false. Later preparation or117/34 validation needs
its own reviewed scope and fresh admission. All predecessor sources and receipts
remain byte-exact; protected log access is not attempted in this package.
