# Local provider validation protocol v4

Root owns `runs/coordination/cho51_p3_provider_qualification_20261028_v4` and all
new sources except `decoder.py`/`test_decoder.py`, assigned to provider_decoder_impl.
A different reviewer seals exact source pins and separately reviews saved actual
results. Work follows the [project policy](../../../docs/PROJECT_EXECUTION_POLICY.md).
No external chat or scheduling dependency applies. Interrupted drafts consumed
no runtime attempt and were not accepted sources.

The fixed runner is a separately reviewed successor to v3 with the same ownership,
cleanup, input retention, stop, memory and time controls. Its16 required inputs
are the nine v4 source/plan/document files, supervision/Job library files, current
policy, three exact004 failure receipts and the prior v1 raw capture payload.
It does not invoke an old launcher or replay an existing attempt.

Root records a fresh `cho51_p3_provider_validation_admission_v4`, unused UUID,
mode `tests` or `collect`, <=15-minute window, exact source map, current base
Python3.12 runtime pins and independent source-review hash. Each mode has its own
admission. The runner atomically creates the unused output directory and retains
its ancestors through receipt writes. Existing identities refuse. Local stop is
`runs/coordination/PROJECT_STOP.json`: present or unknown refuses/stops work.

This small nonnumerical phase has its own Root-issued envelope:4GiB startup and
active RAM,20GiB free disk,512MiB process/768MiB aggregate Job commit,45-second
child/75-second work/90-second whole caller,1MiB payload,one CPU/library worker,
hidden GPUs. The parent additionally runs a deadline watchdog. This does not
amend the proposed006 bootstrap envelope. Tests are pure/injected native-surface
controls; they do not query providers or create fixture files. Collection only
reads selected local logs and publisher metadata. It does not change system
state, privilege, audit configuration or anything outside its new output tree.

Before execution Root verifies source/review/runtime pins, current resources,
stop and fresh absent cache prefix. Parent/child use `-I -S -B -X
pycache_prefix=<phase>/disabled-bytecode/<UUID>`; base executable/DLLs, stdlib
`.py` files and extension libraries are pinned, excluding site-packages.
Runtime/source handles deny write/delete sharing. Windows system libraries are
the declared platform trust base, not evidence of a restart or historical host.

Child creation is atomic into an unnamed noninherited kill-on-close Job and
suspended until membership/limits are checked. Original process/thread handles
remain owned; no PID-based reacquisition or unrelated kill is allowed. A forced
watchdog exit is a failure and cannot establish cleanup. Accepted operation
requires actual normal exit, empty closed Job, process exit, closed handles and
a complete bounded create-once payload. Native Event Log close errors also fail
collection. Query/metadata permission, truncation and unsupported-decoding states
are retained diagnostic gaps; an admitted diagnostic may finish with such gaps.

After each genuine tool return Root saves its chunk/session identity and exit,
with immediate pre/post UTC and QPC observations. The independent reviewer checks
source/runtime/admission joins, complete payloads, query boundaries, raw/template
hashes, supported decoded rows, gaps and owned cleanup. Provisional receipt flags
stay immutable; later review and Root adoption resolve them within the stated
scope. Root updates the handoff and current docs after actual acceptance.

No combination of selected event IDs, template matches, computer labels or PID
absence grants a positive boundary. Historical004 remains failed/consumed;005
stays held. Full restart semantics, old-host association, cross-boot clock order,
persisted-domain exclusion and successor006 remain separately unqualified.
