# Provenance-aware numerical worker and parent v1

This engineering composition connects the accepted provenance-aware restoration
factory with the accepted synthetic linear target route and a reusable parent
entry point. It admits only subject02, LaBraM linear, five shots per class,
seed11, repetition1. The typed adopted route still retains exactly 1,020 cases
over subjects02–52 and all 52 source catalogs. No measured scientific cell,
source fitting, final study freeze or remaining method qualification follows.

`pipeline.run_parent_pipeline(...)` accepts the real recorder, typed plan and
worker context, actual adopted route, fresh workspace, pinned historical origin,
an immutable `factory_template`, backend and independent verifier. It validates
the complete route and delegates one fresh claimed transaction to
`numerical_worker.run_worker_case`. The parent holds the actual OS identity lock
across both durable requests, one backend, two read-only verifier callbacks,
physical proof revalidation, one outer attestation and one engineering terminal.

The immutable outer `NumericalWorkerRequest` contains historical route metadata
and an exact `Factory.RestoreRequest`. The latter binds the same physical claim, pins,
plan and selected state, with its own `workspace/factory/request.json`. Its
compact UTF-8 has no newline. The outer `workspace/request.json` uses canonical
UTF-8 with a newline; its hash and the factory hash remain distinct. The factory
subrequest is written after claiming and before writing the outer request, so
neither digest contains itself. Both are immutable and rechecked independently.

`backend.FactoryNumericalBackend` is initialized with the adopted route,
preserved source fixture, method/protocol configurations, input-audit callback,
independent observer snapshot callback and native execution-scope contextmanager.
Its callable receives `(request, request_path, request_sha256,
locked_case._require_active)`. A no-op callback is rejected. Before array or model
activity it durably consumes `backend-attempt.json`; restoration separately
consumes the accepted factory's `restore-attempt.json`. Reconstructing a backend
cannot replay a used request. Its restore closure calls the actual factory API
inside `target_route.run_target_route`; it does not terminalize the recorder.

The independent observer snapshot is exactly `numerical_calls` plus the keys in
`numerical_worker.OBSERVER_COUNTS`. Successful counts are one full constructor,
one permitted constructor probe, two classifier/backbone forwards, four Profile
A plus two Profile B NPZ loads, four parameterless layout reinitializations in
two disjoint model clones, two empty mask containers, and one factory call and
return. Safe decodes and strict loads are two each; the single head optimizer,
SGD step and backward pass remain separate observations. Initial counts must
be zero. The native execution scope enables numerical work only for this live
request and resets its active state on exit, including failure.

The accepted factory witness keeps source/support/query work at zero. The outer
aggregate records restore1, support/gradient1, query invocation1 and two query
trials, with source updates and measured cells0. Full 223-tensor inventories,
the 402-parameter head mask, finite gradients, unchanged 221 backbone/buffer
tensors, disjoint clone storage, request/provenance roles and exact query metrics
are physically revalidated. Accuracy has no acceptance threshold; wrong fresh
predictions remain wrong. Old historical predictions are never reused as fresh.

`verify_current_execution` consumes the physical execution envelope, both
witnesses and consumed markers and returns an immutable `VerifiedNumericalProof`.
Its fields include both request digests, claim/pins hashes, execution and witness
hashes, both attempt-marker hashes, actual adapted-state digest, rederived metrics
and observed ledgers. Callback return types cannot replace physical validation.
All reads remain bounded and regular-file identities are compared across phases,
including same-byte replacements. Current source/runtime files are rehashed;
the producer, current factory executor and current recorder/target contexts
remain distinct. The accepted factory itself remains unchanged.

Before backend entry, failures record zero numerical counts. After entry they
record incomplete/unknown counts rather than claiming zero or retrying. Durable
outer attestation or recorder intent quarantines errors as `RecoveryRequired`.
`pipeline.recover_parent_pipeline` accepts external request/attestation pins and
a read-only verifier, rechecks physical evidence, and replays only an existing
outer intent. It has no backend argument and never invokes factory
authentication/restoration, a decoder, optimizer or target computation.

Focused tests use fabricated metadata/witnesses and actual recorder locks; no
numerical execution occurs in them. Implementation/source review, guarded tests,
actual bounded episode and external native closeout remain separate evidence.
The fresh phase follows the owner's exact “use the available ram now!” direction
with separately recorded startup4/active4 GiB, disk20 GiB, 600 seconds,
4096/5120 MiB process/Job, CPU/Torch1/1, hidden GPUs and a fresh peer grant.
This document grants no execution or launcher replay by itself.
