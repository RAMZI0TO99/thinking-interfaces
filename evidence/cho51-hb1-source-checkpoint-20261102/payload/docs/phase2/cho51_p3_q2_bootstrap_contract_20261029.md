## Instrumented startup

The exact reviewed caller adds a create-new, original-handle bootstrap journal
in the fresh Q2 namespace. Root's external same-byte dispatch binds the admission
filename, hash, caller source and canonical operation UUID. Before independent
guard startup, the caller may create this bounded diagnostic journal and record

This is an explicit small metadata effect while internal authority checks are
pending; it does not admit compilation, a Python child, or the suite.

The journal retains at most64KiB and32 bounded records. The main caller and its
dedicated guard share the original write handle and a synchronization lock.
Writes are bounded, flushed, and preserved. On a guard fault or early startup
refusal, an independent direct-action deadline is armed for50ms before logging;
the caller records its factual stage/error and invokes the original-process
stop action immediately afterward. Blocked logging cannot postpone that stop.
An independent5s original-clock timer covers initial journal/runspace setup and
is disarmed only after on-time readiness is observed. Guard shutdown has its
own independent1s deadline. The65s hard deadline remains the overall fallback.
A missing or partial diagnostic is unknown evidence, never successful cleanup.

complete loaded-image attestation. Q2 is not a configuration repair or service
