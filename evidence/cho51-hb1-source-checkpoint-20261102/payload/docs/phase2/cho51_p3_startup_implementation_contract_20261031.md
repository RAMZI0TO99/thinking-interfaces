## Focused fresh Q

SQ1 is a new successor of the accepted Q4 supplied-record/retained-reader
qualification machinery. It preserves Q's original 90-second whole interval,
60-second work, five-second cleanup, 512 MiB caller/process and 768 MiB Job caps,
4 GiB startup/active RAM, 20 GiB disk, one library thread and hidden GPUs.
The original five-second bootstrap guard and 65-second hard stop remain.
The current source and runtime are independently reviewed and freshly pinned.
Q's in-memory native owner compilation includes an exact retained Roslyn/reference
assembly census. No LLVM/native observer build, P execution or L import occurs.
The frozen LQ2 native helper qualification is consumed as separately pinned
predecessor evidence, not rerun or attributed to SQ1.

SQ1 explicitly adopts the design's separately reviewed bootstrap-alternative
path. It replaces only the PDH available-memory sensor with the exact already
qualified LQ2 helper's native `Sample` method. Before that helper load, SQ1 checks
its fresh pinned admission, independent source review, adoption and the accepted
LQ2 source/actual/Root chain from retained bytes under the original five-second
deadline and managed stop/disk/512 MiB checks. It then compares the original
helper file identity before constructing the sampler's empty, unused Job.
No `PNative.Owner.Start` is called by SQ1. That helper's P-shaped limits are not
Q's governing limits: the existing independent Q guard still checks the original
controller's 512 MiB private cap, 4 GiB RAM, 20 GiB disk, 250 ms freshness and
60/65-second clocks. Every actual child remains in the separate QNative
512/768 MiB queried Job. The sampler's empty Job/watchdog must close and its
unused process-creation state must be retained. No PDH warm-up or fallback runs.

The fixed Python suite includes foundation/retained-reader/qualification contract
tests and the startup contract tests. Exact method IDs, source set and count are
frozen in the reviewed source candidate and admission; no invented count is used.
Eight UTC controls and two actual malformed-frame/timeout controls remain.
PowerShell syntax checks of the exact pinned startup scripts are admitted Q work.

After the Python supervisor and its children close, the Q caller runs exactly
eight startup-controller controls sequentially: fast, stall, empty, malformed,
reordered, partial, unresolved-review findings and malformed-review identity.
Each uses an unused UUID and the exact reviewed controller/probe source. The Q caller retains
the original controller process/Job handles, stdout/stderr and real exit code.
Its outer Job contains at most the controller and its one probe: two processes,
512 MiB each and 768 MiB aggregate. The inner P-shaped helper cannot raise these
effective limits. No Python supervisor remains alive during those controls.
All control dispatch, waits, cleanup and publication consume the same original
Q clock; insufficient remaining work/cleanup refuses dispatch.

A separate Root-pinned control index is an explicit caller argument alongside
the pinned Q admission. The index pins exactly eight capsules and binds the Q
operation/admission. Each capsule in turn binds that same enclosing Q admission,
preventing a cyclic admission/capsule hash. The recorded allowed command includes
both hashes. Neither the index nor a capsule may authorize another command,
probe, source set, scope or resource envelope. Original read streams remain held
and are rechecked through consumption. The actual Q record includes all nine
outer lifecycles, six diagnostic receipts and two pre-authority refusals and exact source/runtime joins.

## Diagnostic implementation

The controller consumes the exact qualified LQ2 `PNative.Owner` binary and its
accepted source/actual/Root records; no new P helper is compiled. It validates a
closed, bounded capsule and adoption from retained bytes before that load. Its
explicit managed bootstrap trust covers the byte load; the helper's original
native identity is checked immediately afterward and before Job or sensor effects.
The source review must cover assembly initialization/dependencies and that order.

The bootstrap runtime trust is the existing local Windows/.NET/PowerShell host,
not loaded-code attestation. Before helper load, the capsule validates its closed
runtime file references, current executable pin and finite host census, and
requires each non-dynamic loaded managed assembly with a file location to belong
to that set. After the native guard is ready, all runtime files receive retained
byte and native-identity checks before probe dispatch, then full final verification.
This ordering avoids unguarded bulk hashing; it does not substitute an old runtime
receipt for fresh checks. Unexpected runtime files or assembly locations refuse.

The production probe has exactly three fixed origin/domain arguments. Separate
tiny fast/stall and malformed-marker fixture scripts exercise the same controller path under Q only.
The supplied-record contract module is used to validate saved diagnostic records
and by the Q tests; it does not supply runtime authority to PowerShell. Actual
PowerShell controls are required to test the controller implementation itself.

D1 has a fresh original UTC/QPC origin, five-second work boundary, cleanup ending
by elapsed ten seconds and whole return by elapsed fifteen. Two native startup
samples are separated by at least 200 ms. D uses 4096/5120 MiB process/Job caps;
the controller separately enforces 512 MiB private memory for Q control roles.
All roles retain 4 GiB RAM, 20 GiB disk, stop checks, bounded streams and original
process ownership. The direct managed Dispose callback and cancellation
registration join have exclusive ownership of cleanup. No concurrent Poll,
ExitCode or second Dispose may race it. An independent resource/stop guard
continues through retained final verification/publication after Dispose.

Unavailable child exit code and native termination-branch details stay unavailable;
stage markers and disposal completion never prove the prior failed caller's
cause or cleanup. Root accepts only exact observed diagnostic scope. A separate
fresh D admission follows independent source review and accepted SQ1 results.
There is no automatic P retry, production bootstrap replacement or claim that
this diagnostic alone completes P preparation.

The source/record implementation must refuse partial authority, stale or malformed
pins, noncanonical paths, unexpected commands, insufficient time/resources,
unknown original handles, incomplete registration/guard joins, output truncation
and input/output identity drift. Failure consumes its UUID and preserves evidence.
Scientific cells remain 0/1020; the 117 candidates and 34 controls are unexecuted.

The six diagnostic-path controls require two observed results and four marker
refusals, all with original owned cleanup and output identity verification.
The two authority controls use explicitly synthetic reviewed Q fixture records;
they must refuse before helper loading, Job creation or output creation. They do
not provide production authority. Every real-controller refusal retains its
actual outer exit code and original input closure. No test-only bypass exists.
