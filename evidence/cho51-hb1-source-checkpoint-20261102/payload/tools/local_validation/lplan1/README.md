# L1 file-only plan compiler

This source constructs a finite graph from retained text and reviewed decisions.
It does not import candidates, dependencies, execute inspected code, or turn the
physical preparation superset into an execution allowlist. Source files are
parsed only in a separately reviewed and admitted preparation operation.

`compiler.publish_plan(reader, spec, physical, outputs, checkpoint)` consumes the
closed `cho51_l_plan_compiler_spec_v1` seed and the new physical descriptor map.
It emits an inert static plan plus bounded derivation/edge/refusal pages and an
index. Every import, from-import, branch, call and recognized dynamic/native/
resource operation requires a source-hash/location decision. Decisions distinguish
active code, dormant code and exact mediation IDs. Changed, unused or absent
decisions refuse. Root must independently review a complete derivation and adopt
its exact plan before L; an incomplete plan is never runnable authority.

`seed-spec.json` is the concrete preparation seed: accepted package/preimport
seeds, exact candidate paths/pins, known initialization epochs, required early
safetensors guards, source-pinned pytest 9.1.1 plugin names and fixed config.
It intentionally has no invented branch decisions, ABI success, observer binary
hashes, future file IDs or collected node IDs. Its missing branch/call/ABI/native
details must appear as `INCOMPLETE_REFUSED` evidence. A post-Q substitution record
may bind the actual newly qualified native helper and fresh P recipe, followed by
independent review; it cannot resolve missing source decisions implicitly.

The sixteen `CompilerTests` use owned literal text and synthetic descriptors.
They are unexecuted until fresh Q admission. Their results never qualify the
real package graph or the 117 candidate cases.

Revision2 addresses SR1 conservatively. A generic or indirect active call cannot
yield completeness through an include decision or by borrowing a policy effect
ID. Only an exact reviewed dormant exclusion avoids its unresolved-target
refusal. Recognized import/code/native/resource spellings require an unshadowed
builtin or a single exact unaliased module-root import; possible assignments,
parameters or other rebindings anywhere in the source refuse that root. No
alias, getattr, container or returned-callable analysis is claimed. Active
dynamic imports additionally require one absolute literal target exactly equal
to the decision target. These conservative restrictions may retain unresolved
legitimate package calls; they cannot be resolved by fabricating generic-call
include decisions. Source review of dormant exclusions remains mandatory.
