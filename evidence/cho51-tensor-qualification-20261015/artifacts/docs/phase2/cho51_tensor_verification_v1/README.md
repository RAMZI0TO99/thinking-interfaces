# Adopted-51 finite tensor-verification successor

This separately versioned engineering stage preserves the historical 52-target
helpers and the exact 51-target amendment: subjects02–52, four methods, five
seeds, five shots per class and one repetition. It does not open an experiment
attempt, grant a new compute lease, sign the freeze or admit a scientific result.

`contract.py` prepares one immutable `Cho51TensorRequest` from a typed case plan,
the publication stage's `Cho51PublicationBinding`, independent source provenance
and detached method/protocol configuration snapshots. The request digest binds
the complete serialized payload. The exact manifest location is checked
lexically; physical path, byte stability and resource admission belong to the
launcher and child. `load_tensor_request` repeats the pure validation in the
child with exact outer and nested schemas.

`validate_tensor_witness` admits an exact digest-only witness: schema, request
digest, case identity, selected publication identities and literal
`training_performed=False` must agree. A fabricated callback can produce this
object, so its native-supervision, selected-tensor and scientific-admission
properties remain false. The launcher's separately checked native execution
receipt is necessary to distinguish real child execution from fabricated test
metadata. Full selector evidence, cohort review, final owner freeze and science
budget remain separate requirements.

`test_contract.py` contains fabricated-metadata boundary checks for roster,
source, paths, independently pinned configurations, detached serialization and
strict witness admission. It neither opens publication files nor constructs a
model. Prepared source and tests do not constitute executed qualification;
execution status is recorded in the dated project handoff and fresh evidence.
