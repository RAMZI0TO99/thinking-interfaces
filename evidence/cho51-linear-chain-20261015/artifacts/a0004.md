# Complete the linear selector through bounded native fragments

This new frozen executor extends the accepted ten raw linear folds through six
sequential fold Jobs, containing 16, 16, 16, 16, 16 and 12 new distinct folds,
then a separate fresh final-fit Job. Each externally pinned request binds the
exact next canonical remaining roster slice, current chain head, source bundle,
root origin and unused output directory. No accepted predecessor is edited.
Every native Job retains the unchanged 600-second, 4,096 MiB process, 5,120 MiB
Job, 10 GiB startup RAM, 4 GiB active RAM, 20 GiB disk, one-thread and hidden-GPU
limits. Resource gates and genuine peer pauses remain authoritative.

The executor entry point is `run_probe(output, method_config, request=request,
origin=origin, chain=chain, set_protected_inputs=callback,
checkpoint_control=callback)`. Fold requests execute inherited public
`run_fold` calls only. For N folds they perform exactly 50N source and N support
updates, 2N fresh optimizers, two safe baseline decodes and two strict baseline
loads. Raw folds are persisted individually before subsequent work. Canonical
public completeness verification must refuse every raw incomplete fold.

All fragments reuse the original accepted read-only synthetic fixture: exactly
213 files, 734,579,463 bytes, 52 subjects, 64 channels, Profile A at 512 samples,
Profile B at 800 samples, the four canonical shot levels and withheld queries.
The frozen `_existing_fixture` reconstructs catalogs and metadata without a
builder, regenerated arrays, added files or writes into the original fixture.
All four outer-target-02 paths are denied throughout model construction,
independent lineage verification, source fitting and inner query prediction.

The existing audited safe baseline and its independently pinned configuration
produce the full 12-block/embed-200 classifier with 5,818,138 parameters. Exactly
402 head parameters in two tensors are trainable; the complete frozen backbone
and buffers must remain byte exact. Independent canonical `_new_model`
reconstruction must reproduce initial/template digest
`90a9d34ecba2aa96a942f7bd70724f63c2071042141935dbbcd78e0b373b89a7`
and selector contract
`8397d34ee0a2280b406071e045988f98b1b73ce21fcecc0b9834518cd21993b1`
with disjoint storage. The declared complete budget remains 5,253 updates.
No canonical model, source-fit or loader implementation is patched.

`origin.verify_chain` authenticates every previous record, its native execution
proof and exact source/runtime lineage before protection and after release.
The pure metadata plan and partial collector grant no execution authority.
Combined raw coverage remains explicitly incomplete until all 102 folds exist;
incomplete finalization must refuse before any final fitting. A complete roster
is never used to manufacture an incomplete-refusal claim.

Final mode requires all 102 authenticated native-origin folds and a concrete
origin-verifier capability. It calls this version's staged selector's
`complete_final_fit`, which checks the full roster and native origins, computes
the exact rational winner and performs a fresh all-51-source fit from the
unchanged initial state. This final Job observes exactly 51 source updates, no
support update and one fresh optimizer. The actual fitted model, winner settings
and complete evidence must pass the canonical public complete-evidence verifier.
Canonical `run_selection` is not invoked. A `finally` block clears canonical
resident input arrays even if finalization fails before its evidence boundary.

This selector preserves the previously accepted incomplete gate while correcting
the earlier unexecuted final branch's roster comparison: canonical fitting
returns a tuple, whereas the detached contract contains a JSON list. The new
version compares their ordered values before evidence serialization. The frozen
predecessor is unchanged. Actual final-branch qualification requires the final
native Job and the public evidence verifier.

Final mode saves exactly one complete CPU float32 safe checkpoint, not a
head-only fragment. The 223-tensor, 5,818,138-element state is bounded to 64 MiB,
written exclusively, fsynced and hashed. The native checkpoint-control callback
binds those exact owned bytes before one round-trip decode. Tensor names, shapes,
dtypes, finite values, all bytes and the canonical model-state digest must match
the actual fitted model. This adds one safe save and one decode to the two
baseline decodes, without an additional model load. `full_v1` describes the
complete state encoding; no selected-source publication or public restoration

The common lineage recipe remains pinned to the historical first-candidate

Complete `selection-evidence.json` alone has a narrow 32 MiB metadata limit;

Each fragment writes raw `fold_XX.json` files when applicable,
`partial-collection.json`, `optimizer-observations.json`,
`finalization-refusals.json` and `probe-result.json`. Final mode additionally
writes `selection-evidence.json`, `selected-source.safetensors` and
