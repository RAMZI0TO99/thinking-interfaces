## Capacity and capture decisions

Unchanged caps are global256 files/64MiB; fixtures160/32MiB; supervisor40/8MiB;
caller40/20MiB; closeout16/4MiB; per-file8MiB and every fixed role cap. The report
proposal leaves role-specific arithmetic headroom, not transferable slots or a
complete native/bootstrap/compiler/test allocation. All failed, unused, partial,
temporary, copy and unexpected writes are charged. Q/S/D/E staging is not free;
no S projection file, extra journal or seventeenth closeout role is reserved.

Raw stdout/stderr/tool-return each retain1MiB and external return64KiB. An allowed
1MiB control-byte stream may require6291456 escaped JSON payload bytes before
envelopes; two may require12582912. Thus universal inline escaping into the
unchanged return caps is infeasible for that strategy. This is not proof that
every run or every retained-raw design is infeasible. Retained raw channels and
bounded references still need complete original capture/framing/EOF/custody and
packing proof; this phase does not implement or qualify that alternative.

mathematical impossibility. Keep process512MiB/Job768MiB; RAM4GiB/disk20GiB;
