# CM3 independent evidence and failure/capture design

2 November 2026. **Seven-file design independently accepted with no findings.**
The [design package](cho51_p3_component_evidence_v1/README.md) specifies an
independent supplied-byte CM2 event verifier, complete collection/event/table
joins, and the failure-domain/capture requirements for a real case/suite boundary.
The verifier and join are not implemented by this design step. No code execution,
test, runtime admission or Git operation occurred; P stays disabled.

The verifier will independently reconstruct observable ordering, primary outcomes,
negative/failfast state, fixture ownership, complete declared trace groups and
prefix/whole hashes. It checks the frozen CM2 schema directly rather than replaying
CallbackModel or coercing records to CM1. Raw full 764/32 collection precedes the
separate 732/30 and 700/28 projections, and context/table bindings use exact raw
digests. Matching counts or caller-created Facts cannot substitute for those bytes.

The central limit is explicit: CM2 serializes no cleanup_done, duration or
close_suite transition, nor its final refusal latch. Identical complete bytes
can accompany a later producer refusal. Thus valid all-PASS bytes establish only
supplied transcript consistency, never actual cleanup, original trace/subcase
completeness, native custody or runtime acceptance. A future enlarged checkout
requires its own full roster/selection/schema adoption; the frozen CM2 target
cannot hide new verifier tests.

The failure contract identifies pre-result SkipTest formatting, assertions, mock
diagnostics, helper exception formatting and reference cleanup semantics. A real
nonformatting case/suite successor needs separate semantic-equivalence qualification
and original lifecycle evidence. The capture contract retains exact original
bytes, observer chunk order, EOF/error/closure, complete tool envelopes and full
parent accounting. All input/output ceilings, clocks and resource guards remain.
Complete capture and operation feasibility are still NOT_ESTABLISHED.

There are **32 unimplemented, unexecuted design scenarios**, not new test methods
or passing controls. The source roster remains **764 identities / 32 modules,
248 proposed selections**. The prior conditional normal bound remains 1,000
records / 512,000 bytes. The proposed four-input maximum of 4,259,840 bytes is
only supplied-input arithmetic; decoded/copy memory and allocation are unproved.
