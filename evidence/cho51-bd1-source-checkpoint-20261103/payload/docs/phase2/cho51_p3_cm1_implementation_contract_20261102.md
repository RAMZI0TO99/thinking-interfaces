# CM1 source-only implementation contract

2 November 2026. This new implementation adopts the accepted
[CM1 design](cho51_p3_component_model_design_20261102.md) without editing its
eight files or HB1/SC1/LQ19 predecessors. The package is
`tools/local_validation/cm1`, with seven Python files and one README. Root owns
registry, collection, collection tests and metadata; cm1_protocol_author owns
protocol, refusal and protocol tests. Independent source and metadata reviewers
are distinct and message-only. Root alone publishes phase records.

## Exact implemented scope

- Immutable successor registry: all 732 ordered source identities / 30 modules,
  exact 216 selection, exact new 32 IDs and test pins; external candidate pins
  exclude their own hash. No file read or source discovery occurs in the registry.
- Canonical collection supplied-data verifier, maximum 1 MiB, full successor
  conservation before the unchanged 700/28 projection into frozen HB1. Both
  collection and projection digests are retained. Selection discharges no cohort.
- Supplied identity-only namespace bijection, empty bootstrap anomaly lists and
  exact eight-surface restoration tokens, including create=True original absence.
  These are data checks, not real object inspection or loaded-source evidence.
- Canonical 13-field events: at most 4,096 lines, 512 bytes per line, 2 MiB total;
  contiguous sequence, exact operation/roster/selection and footer digest joins;
  active-case order, one primary PASS, complete subcase and trace groups, sticky
  negatives and failfast. A partial valid transcript remains incomplete facts.
- Finite supplied code/location and fixture tables. Fixtures join exact selected
  module/class owner and affected ordinal tuple. Tables remain unauthenticated.
  In-case fixtures and nested failfast unwind are refused until a reviewed finite
  mapping exists. A maximum 4,096 supplied code/location pairs is conservative;
  no runtime coverage or original traceback traversal is claimed.
- Ordered raw chunk model, 1 MiB each stdout/stderr and 4,096 chunks; sticky
  failure/reentrancy and byte-preserving snapshots. This is an in-memory model,
  not capture of a real pipe/tool response. Report-only reservations stay the
  30-file / 17,711,104-byte minimum, not a complete allocation.
- Supplied disjoint guard surfaces and integer-second deadline minima; no clocks,
  live handles, continuous sampling or process control. Operational dispatch
  unconditionally refuses even if supplied checks succeed.
- Exactly 32 declared model methods, 16 in each new test module, with negative
  transcripts/subcases. No test, import, Python parser, AST, compiler, native
  program or Git command is run during this phase.

All model result authentication/execution properties remain false. No result
produced here is COMPONENT_MODEL_ONLY, Q acceptance, P/L/V admission or science.
Reference tables and token comparisons do not substitute for original producer
custody. Event verification is separate from collection verification; a future
reviewed operational aggregator must bind both plus raw streams, input/final
verification, native ownership, full census and separate actual result review.

## Effect and feasibility boundary

The companion inventory enumerates every selected method and new declaration
from exact source text, its pin, phase, direct effects and unresolved bounds.
Text inspection is not Python parsing, discovery or complete recursive closure.
The new local functions use bounded in-memory data work and supplied checkpoints;
those callbacks are explicitly untrusted model inputs and may have arbitrary
effects. No model checkpoint is a native resource guard.

The inherited 184 methods and every new method retain recursive import, fixture,
exception/formatting and callback-depth obligations. A fixed refusal ceiling does
not prove every allowed path fits. The complete 216-method effect/subcase/event
and producer/capture budget remains NOT_ESTABLISHED. The finite retained importer,
real collector/result producer, independent native guard, full allocation,
original transport and asynchronous lifecycle remain unimplemented/unqualified.
The next source-only step must close that inventory and design the smallest
reviewable retained-loading/result-producing successor before any admission.
