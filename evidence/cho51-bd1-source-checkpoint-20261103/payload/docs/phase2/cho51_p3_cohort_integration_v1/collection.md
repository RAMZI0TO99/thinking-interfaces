# Complete current collection before views

This is a supplied-data integration contract, not an implemented importer or
test loader. A future original collector must independently enumerate all C
under original source/runtime, stop, clock, resource and custody controls. A
descriptor copied into a report cannot prove such enumeration occurred.

verify_collection(collection_raw, cohort_raw, descriptor_raw,
expected_cohort_pin, expected_descriptor_pin, operation) takes only exact raw
bytes, exact pin tuples and operation. It independently parses expected context,
checks operation/K, verifies the entire report, then derives views. No supplied
Facts, cached order, mutable table or previously verified object bypasses parsing.
An internal fixed model checkpoint is not a native guard or runtime admission.

The closed collection schema cho51_cm6_supplied_collection_v1 has fields schema,
operation,context,complete,modules,tests. complete is exact True. modules and tests
have exactly D's counts/order, with no omission, duplicate or equal-count swap.
Modules have the frozen collection fields module,bytes,sha256,loader,load_tests,
partial. Pin fields match D; loader equals the exact frozen cm1.collection.LOADER
literal; load_tests and partial are exact False. Match every baseline module pin
before looking at cohort membership. A changed inherited module refuses the
whole integrated context, not merely an optional historical view.

Tests have the frozen ten fields id,module,class_name,method_name,source_module,
source_qualname,skipped,deselected,expected_failure,xfail. Split each expected id
into module,class,method; require exact row equality, source_module==module and
source_qualname==class+'.'+method. Require exact False on all four eligibility
flags, including HELD rows. Unknown owners, inherited aliases, foreign source
qualnames, missing or extra modules and partial reports refuse before projection.
These supplied checks do not establish original code bytes, loader execution or
absence of monkeypatching. D schedule/debt is checked separately; it cannot be
smuggled into an eligibility flag or used to hide a row.

After full C conservation, derive these separate immutable views in memory:

1. Q:360 exact identities in the stable Q order, with explicit Q-index-to-C-index
   mapping, referenced current module pins and the complete HELD identity/debt
   complement. Canonical view schema cho51_cm6_cohort_view_v1 has closed schema,
   operation,context,cohort,modules,tests fields; cohort is Q.ids_sha256. Its
   modules/tests preserve the checked report fields, filtered and ordered to Q.
2. H:836 identities/36 modules in frozen CM4 order. Construct the exact original
   cho51_cm4_supplied_collection_v1 envelope, with operation and its original
   roster/selection literals, by filtering the already checked supplied rows.
   Independently run the frozen CM4 collection verifier on those projected raw
   bytes. Its distinct CM2/CM1/HB1 projections then retain their exact schemas.

Both required views must succeed before returning completed collection facts or
allowing producer BEGIN. Never replace observed pins/owner fields with expected
ones to make H fit. A wrong H source pin or missing historical row fails the
whole integrated collection. The complete C raw hash, Q-view raw hash, H raw hash
and nested CM2/CM1/HB1 raw hashes stay separately named; Q/C/H identity digests
are not interchangeable with any report-byte digest. Projections are memory
values, not additional filesystem slots or original execution evidence.

Returned facts contain immutable tuples/pins, O/K, exact C/Q/HELD counts and
separate projection hashes, with authenticated=False and execution_accepted=False
unconditionally. All candidate117/V34, held qualification debts and original
effect/lifecycle/capture/native obligations remain outside acceptance. No future
current census is assumed from the initial876 rows; each added row needs an
explicit reviewed D successor and fresh byte checks, even when Q is unchanged.
