# CM1 original operation and isolation boundary

## Scope and process ownership

CM1 is a new versioned successor, not another mode added to frozen LQ19. The old
child refuses on entry, has only32/100/384 protocol choices and a collection
partition that misplaces qd10. It omits the SC/HB modules. No old launcher,
watcher, failed UUID, model host or consumed admission is reused.

The future operation has one original outer caller/guard owner, its existing
bounded supervisor relationship and one sequential test child. No parallel
test pool, provider service or extra computational worker is added. Every owned
helper/compiler/process, if needed by the actual implementation, must be named
in the final finite command/producer graph and retained Job/handle evidence.
Do not kill unrelated processes or infer cleanup from PID absence.

The original outer guard starts before runtime/bootstrap effects. It retains
the original process/Job/pipe handles and independent time/resource/stop evidence
through cleanup. A newly source-reviewed successor must preserve the known
containment, startup and native-reader checks, including failure before a Job
exists. This design does not qualify that successor or its native helper.

## Live guards cannot observe model replacements

The eight patch surfaces and40 expected normal-path module/shared applications
are enumerated with source locations in source-map.json. They include os.lstat,
shutil.disk_usage and ctypes.WinDLL, along with buffer/error functions and two
supervisor attributes. There are also three fake-instance patch applications
and a disposable fake write_new assignment. Counts describe source paths, not
observed patch execution; early failure need not reach every patch.

Live RAM, disk, stop, source retention, native identity and process ownership
must not call these mutable globals inside the interpreter under test. The
actual enforcement remains in the independently owned original native/outer
boundary. Any child checkpoint bridge uses separately pinned, prebound native
handles/function pointers and private bindings unreachable through the reviewed
patch surfaces. A Python guard built on the same mocked os/shutil/ctypes objects
does not satisfy the contract. Python threads or callback checks alone cannot
bound a blocked call or prove its termination.

Before each selected case, compare exact module/attribute objects, namespace
bindings, importer state and the required original absence of attributes patched
with create=True. After the complete case lifecycle and cleanups, compare them
again before accepting an outcome or starting another case. Use bounded private
references and built-in dictionary/type operations; do not invoke arbitrary
descriptors to perform the check. Restoration failure is sticky: fail/consume,
stop further cases and perform only the original bounded cleanup. The runner
must not silently repair mutated globals and continue.

These before/after checks complement independent continuous enforcement; they
do not prove that a mocked value never existed during the test. Each permitted
patch occurrence must be assigned to its exact method/effect row. Unknown patch
surfaces, additional threads/processes/files or native calls require explicit
source review and accounting, or refusal before admission. The current trace
does not close the184-method recursive effect table. Real ctypes buffer/layout
work, the16MiB hash case, RLock and datetime.now must be charged as runtime work.
The wall clock is test data, never an operational deadline source.

## Finite state and evidence order

The future controller follows NEW → ORIGINAL_GUARD_READY → INPUTS_RETAINED →
BOOTSTRAP_RECONCILED → FULL_COLLECTION_VERIFIED → SELECTED_EXECUTION →
FINAL_VERIFICATION → OWNED_CLOSED. These are implementation states, not evidence
that the transitions happened. All required original operation consumption,
source approval, parent mapping and provider/accounting prerequisites must be
established before effects. If unavailable, the operational entry stays
REFUSED_UNADMITTED; no fake HB1 confirmation can advance it.

At every stage bind operation, authority, source/runtime/roster pins, original
clock domain and exact producer/output map. Missing, mismatched, ambiguous,
extra or stale evidence refuses. Once effects/claim may have occurred, failure
is consumed and ambiguous custody remains UNKNOWN; no resume, retry or new UUID
inside the same operation. A later diagnostic cannot make the old attempt unused.

No result callback can publish COMPONENT_MODEL_ONLY. Acceptance requires the
complete independent external return, all216 selected terminal outcomes after
complete732 discovery, event conservation, unmodified source/runtime inputs,
final output census and actual owned closure, plus separate actual review.
An exit0, model census or report generated by the tested child is insufficient.

## Unchanged clocks and limits

Keep whole90s, work60s, fault-relative cleanup at most5s, hard65s and child
absolute55s. Where used, suite40s/native12s/fault2s remain subordinate maxima.
Startup5s, two samples at least200ms apart,250ms freshness,512MiB process/
768MiB Job,4GiB available RAM,20GiB free disk, one CPU/library thread, hidden GPUs,
stop controls and original ownership remain. QD45/53/55 limits remain QD-only.

Let T0 be the original caller origin, F the independently justified remaining
final verification/closure work and M the explicit margin. Child completion is
bounded by min(T0+55, T0+60-F-M). A suite also obeys its own40s maximum within
that bound. Never launch a child or another case if remaining work cannot include
its reviewed worst-case cost and final reserve. Cleanup ends at the minimum of
fault time+5s and original hard limits; it does not refresh the work clock.

F, M and the stage costs are not currently established. The historical37.76s QD
prefix is not a cost bound for CM1. No retained compilation or outside-clock
collection may manufacture headroom. Existing qualified read-only inputs may
be considered only with exact independent compatibility/source/runtime review;
no unreviewed helper is precompiled to escape the clock. Timing feasibility and
actual startup/control behavior remain separate qualification prerequisites.
