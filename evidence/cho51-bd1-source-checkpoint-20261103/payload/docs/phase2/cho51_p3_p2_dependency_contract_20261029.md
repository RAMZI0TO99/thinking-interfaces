# P2 dependency map and file-only preparation contract

29 October 2026. Implementation-specific successor to accepted P1 engine
qualification. This supplement is adopted separately for Q and P, each against
exact reviewed sources and an unused operation. It does not itself admit work.

## Concrete physical scope

The [recipe](../../tools/local_validation/p2/dependency_recipe.json) selects the
live project source census, exact metadata seeds/assets and dynamic planner
inputs; the new observer and frozen supporting sources; a fresh base Python;
every installed .py/.pyi/.pyd/.dll outside bytecode caches; all installed dist-info
trees; finite reviewed package resources; and Git executable/config/repository
bytes. The stale venv executable is excluded. Protected EEG data, weights,
bytecode, startup .pth and unbounded personal resources remain prohibited.

The [coverage rationale](../../tools/local_validation/p2/dependency_coverage.md)
traces the actual broad import paths and fixes Git, MNE, Matplotlib and Torch
configuration/search expectations. Dormant code is a physical superset, not an
execution allowlist. Unexpected later resource, origin, plugin, native-search
or helper activity must refuse. It is not authorized discovery.

Optional native-search directories receive retained absence observations or
complete selected DLL censuses. Bounded PE reads inspect static and delay import
tables through original file handles without image loading. Each non-platform
edge needs selected physical candidates. Multiple candidates are retained as
explicit alternatives; P does not choose a Windows loader search winner.
Exact API-set names map to declared System32 hosts, never a prefix wildcard.
The reviewed API namespace source hash is freshly compared. Used platform paths
must exist as ordinary non-reparse files under the declared local Windows trust.
OS trust does not waive the physical reader's single-link/NTFS/reparse guards,
and is not cryptographic loaded-code or ABI attestation.

## Bounded file-only P operation

P preserves 300 seconds whole, 240 work, 5 cleanup, 4096 MiB process/caller,
5120 MiB Job, 4 GiB startup/active available RAM, 20 GiB free disk, one library
thread, hidden GPUs and a local stop file. Original UTC/QPC clocks cover startup,
pinning, work, publication and cleanup. An independent caller guard and hard
245-second kill deadline remain active. One atomic Job owns the sole supervisor;
no PID reopen, unrelated-process kill or compiler process is permitted.

The immutable physical pin index joins bounded pages with exact path, byte and
SHA256 tuples. It must equal the selected union. P retains native file identities
and ancestry, checks initial/final membership and same-handle bytes, and publishes
bounded output pages. Limits remain 25,000 files, 4 GiB selected bytes, 2 GiB per
file, depth32, 64 KiB hash chunks, 8 MiB/200,000 nodes per JSON, and 64 MiB/256
output files. Pagination does not raise any limit or permit truncation.

Admission, reviews, pin pages, Q qualification and native artifact are separate
retained control inputs; they cannot form self-hash cycles in the physical map.
Explicit extra physical inputs have a reviewed exact list. Active handoff pages
and newly written attempt records are not dependency-code selectors. Raw Git
objects are opaque file bytes; no Git invocation or object expansion occurs.

P loads the Q-emitted managed native PE by exact retained bytes and checks its
qualified native identity. It does not invoke Add-Type, compile dependencies,
import candidates/packages, open data/weights, run Git or use the network.
Only the pinned observer and standard bootstrap modules execute. The child
hands output descriptors over its original owned stdout pipe. Parent receivers
verify each exact byte digest and native identity and retain their original
handles through publication. Path/hash alone is insufficient for that handoff.

## Q qualification and independent gates

The new P2Q successor inherits Q4/P1Q ownership, clock, memory, resource, pipe,
fault and timestamp controls. Q remains 90 seconds whole,60 work,5 cleanup,
512 MiB process/caller and768 MiB Job. It uses a fresh exact base runtime and
PowerShell host plus pinned Roslyn/reference assemblies for native emission.
The P helper is emitted in memory, published create-new through its original
handle, loaded from those readback bytes, and exercised with an empty Job to
query P limits and close native ownership. This does not substitute for an
actual admitted P child operation.

The reviewed expected suite has176 methods:31 foundation,30 reader,12 Q
protocol,35 P1,31 paged-map,17 PE parser/resolution,20 P protocol. Eight UTC
controls and two native fault probes remain separate. Counts are planned until
actual results are independently reviewed. Test fixtures are small JSON-only
files under the unused owned Q attempt; no package imports or numerical tests.

Q source acceptance, scoped Q adoption, fresh admission, actual tool/caller/Job
evidence and a different actual reviewer precede Root Q qualification. P checks
the full qualification joins, exact test/control counts, native artifact,
independent reviewers and chronology. P additionally needs exact source and
proposed physical coverage reviews, scoped P adoption, fresh admission, actual
native observations and separate pin/coverage/result review. No implicit stage
advance occurs. A failed or uncertain attempt is consumed and preserved.
