# P1 preparation-engine qualification runner

This new version is Q-only. It qualifies the proposed P1 physical-map engine;
it does not perform the actual P dependency closure, L collection, V117/34 or C.
The [P1 supplement](../../../docs/phase2/cho51_p3_p1_preparation_contract_20261029.md)
requires exact source review, Root adoption, fresh admission and a distinct
actual-result reviewer. No source file grants execution.

Root owns this directory. p_preparation_impl owns the initial three P1 engine,
test and README files. Sources under q4 and v1 remain unchanged. The new runner
adapts Q4 by changing its source/phase/module identities and predecessor to the
accepted Q4 qualification, adding P1 engine/tests and the original Q4 reader to
the exact source set, and registering both module namespaces before executing
the new tests. Protocol source-review status is ACCEPTED_SOURCE_P1Q. C# helper
and Job adapter behavior remain byte-identical to Q4; native reader/test copies
and protocol tests retain the reviewed behavior under their new namespace.

The source-time suite is 108 methods:31 frozen foundation,30 retained-reader,
12 protocol and35 P1 engine methods. This is an expected roster, not a passing
claim. Exact full IDs are pinned before admission and checked against collection
and execution. P1 tests cover recipes, bounds, role/scope/pin refusals, actual
four-role retained JSON observations, directory membership, hardlink and writer
refusals, failed-session poisoning and defensive values. Reparse injection is
not qualification of a real reparse fixture. All files created by tests are
small JSON fixtures below the fresh owned attempt, except bounded result records.

The Q4 safeguards are retained: original caller UTC/QPC origin, two startup
samples, explicit UTC parsing and eight caller timestamp controls, independent
startup/active/fault/shutdown deadlines, bounded original-handle bootstrap
journal, read-sharing input retention, same-byte code execution, atomic unnamed
kill-on-close Jobs before resume, original process/pipe/thread handles, bounded
framed EOF, two native badframe/stall fault controls, and complete external tool
return followed by independent actual review. No PID reopen, tree sweep or old
launcher replay is permitted. Q1 remains consumed with unknown cause/cleanup.

Limits stay90s whole/60s work/5s cleanup,512MiB process and caller/768MiB Job,
4GiB startup/active RAM,20GiB disk, one library thread and hidden GPUs. Inputs
include a fresh exact base-runtime census (up to2000 files/64MiB), reviewed
PowerShell7 executable, accepted source/design/supplement joins and the Q4
predecessor. Same local Windows/filesystem/PowerShell/.NET/PDH trust assumptions
apply; this is not loaded-image attestation or hostile same-account isolation.

The caller's in-memory Add-Type is an explicitly admitted Q bootstrap effect.
It does not make this runner a file-only P caller. Actual P needs a separately
reviewed physical recipe and caller under its own300s/240s/5s envelope; do not
change this runner's stage or limits to manufacture P admission.

Reports retain all historical/restart/boundary/complete-dependency/future-launch
and scientific flags as false. The engine returns a proposed physical map only;
coverage review, ABI/loader qualification, actual acceptance and later admission
are separate. The117 candidates,34 successor controls,full26 qualification
matrix and original48 custody cases are not completed by this suite.
