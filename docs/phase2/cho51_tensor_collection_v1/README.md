# Adopted-51 native tensor receipt collection candidate

`collect_cho51_tensor_receipts(project_root, route, publication_collection,
requests, receipt_pins, *, expected_source)` consumes an existing publication
collection plus independent per-case request, bundle, native receipt and
witness digests. It does not launch a process or create a new attempt.

Before file I/O it requires the exact 1,020 adopted cases: subjects 02–52,
four unchanged methods, seeds 11/23/37/53/71, five shots and repetition one.
Requests match every publication field, source, root, owner, route method and
protocol configuration. Publication claims and rows cover exactly that roster.
Every typed row and key is reconstructed to validate score bounds, scalar types
and cell digests even when a caller bypasses frozen dataclass constructors.
All 1,020 bundle paths, native directories and request digests must be distinct.
The same one-case execution proof cannot qualify the complete roster.

Each proof uses the existing qualified launcher's `load_bundle` and
`admit_native_receipt`; the latter freshly queries native Job absence and
checks execution limits, source/runtime/assets and actual child scope.
Receipt/witness bytes are checked against the independent pins before and
after admission. The complete input payload and exact no-training tensor
witness must match the typed request. A second full admission pass retains
physical identity for bundle, input, receipt, witness, admission and scope
files, detecting earlier-case changes and same-byte replacement. These checks
provide bounded rereads, not a filesystem lock.

A successful production call marks the complete native tensor receipt roster
and selected tensor verification true. Full selector evidence, broader selected
publication admission, combined selection/publication/tensor admission and
scientific admission remain false. Upstream publication collection is an
already verified typed input; this layer does not rerun publication collection
or establish scientific fitting history.

`test_collection.py` is prepared engineering coverage using fabricated typed
1,020-case metadata and mocked launcher I/O/native admissions. A small helper
test checks temporary file bytes and physical replacement. Passing this suite
does not mean that 1,020 real tensor receipts exist or that this complete
production path has run. No test execution has been performed by the authoring
worker; current execution and qualification status belong in the dated root
report and evidence package.
