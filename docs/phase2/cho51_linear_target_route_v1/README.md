# Synthetic linear target-support/query candidate

This separately versioned candidate qualifies one engineering route only:
Cho2017, subject 02, `labram_linear`, five shots per class, seed 11, repetition
1. It does not write a scientific cell, change an accepted recorder receipt or
qualify the full worker. Numerical execution requires the independently pinned
fresh Windows native Job described by the target-route plan and coordination.

`run_target_route` accepts the preserved fixture and authenticated catalog,
selection, episode, asset and provenance inputs. Its `restore_adapter` callback
must authenticate frozen historical publication/restoration/recorder proof
bytes and perform one separately counted fresh bounded restoration. The
callback returns the actual canonical `LaBraMTunedAdapter` holding the exact
selected 223-tensor source state. Historical proofs remain historical: new
Git/runtime context is recorded separately. The unchanged single-root source
store/factories and public complete-evidence verifier are not requalified.

The candidate reconstructs the canonical 52-subject selection and fixed
1/5/10/20-shot nested episode. It requires the exact preserved synthetic
42-trial order: support rows 0–9, fixed query rows 40–41 and unused pool rows
10–39. The canonical 60 Hz A/B loader rechecks actual target bytes, row IDs,
labels, montage, preprocessing, variant and raw-source hashes. The real adapter
constructs the real manifest runner, which independently binds those inputs
again. The two canonical bindings decode six target NPZ payloads total: each
reads Profile A once for catalog auditing and once for array binding, then
Profile B once. The parent reconstructs the exact
synthetic catalogs from authenticated original identity metadata and array byte
hashes. Other subjects' arrays are not decoded for this target episode.

The selected support settings are linear, one full-support SGD step, learning
rate 0.001, no partial depth and query batch size eight. Read-only Python
profiling observes the unchanged canonical support function, classifier
forward, Tensor backward, plain SGD step and manifest prediction. It verifies
the exact ten support signals/labels and the two query signals at the actual
calls. At SGD entry it requires only `head.weight`/`head.bias` (402 parameters),
finite gradients, absent frozen/source gradients, eval mode and the exact
selected starting state. Per-tensor hashes require a changed head with every
backbone tensor and buffer unchanged. Caller source, runner-owned source and
adapted clone must have disjoint tensor storage. One inference-mode query
forward follows adaptation; source and adapted state remain exact through inference. Profiling
is restored on success or refusal and chains a prior profiler.

Query labels are validated as immutable episode identity, then used only for
post-inference metrics. They do not enter support loss, optimizer, candidate
selection, step count or stopping. The actual single-route witnesses establish
that the exact support inputs reach adaptation and the unused/query rows do
not. Metadata tests reject query-label substitution, self-consistent foreign
envelopes, partition/order tampering, wrong plans, identity/hash/transform
changes, state drift and provenance collapse. They deliberately perform no
model construction, adaptation, restoration or inference. A second numerical
query-label-swap run is not included in the one-support-update budget.

On return the witness records zero current source updates, one support update,
one restore callback, one two-query classifier inference call and zero measured
cells. Historical 5,253 updates and 102 folds are reused, never replayed. The
caller independently witnesses constructor/checkpoint decode counts, validates
all 213 input hashes before/after, persists the engineering attestation and
checks native cleanup. This module writes no files, claims no case and has no
automatic retry/recovery path. A refusal preserves its attempt for a separately
reviewed repair. Scientific admission, final owner freeze, cohort/prior-training
lineage and full worker qualification remain pending.
