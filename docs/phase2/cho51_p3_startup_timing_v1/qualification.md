# Implementation and independent acceptance gates

Design acceptance authorizes no execution. The 36 scenarios below are planned,
unimplemented and unexecuted. They are diagnostic qualification obligations,
not candidate117, V34 or a new passing-test count.

1. Implement a new versioned QD-only caller/supervisor and pure closed-format
   validator plus bounded native journal, with explicit file ownership. Preserve
   all frozen LP17/LQ17/lplan14 sources and their failed attempts.
2. Independently review every source difference, append/close state machine,
   early initialization cleanup, original predicates, exact dependency/runtime
   recipe, typed-return rejection and output ledger. No mutable shared write
   capability or new arbitrary logging is allowed. Source acceptance is static.
3. Source-review a finite nonnumerical qualification strategy for these scenarios.
   Pure/injected controls and actual native fault/ownership checks must be
   distinguished. A fake callback, simulated close or file parser cannot establish
   real retained-handle closure. If they cannot fit a fresh reviewed qualification
   envelope, preserve them as unexecuted; do not label QD itself their completion.
4. Separately admit at most one new QD attempt for bounded investigation when its
   source/custody/allocation gates hold. That investigation may precede full Q
   acceptance precisely because it cannot qualify or advance beyond Q. Keep every
   executed and unexecuted control explicit. Separate actual review can accept
   only its selected prefix and owned lifecycle, never the implementation's full
   qualification. Failure consumes the attempt and requires review before any
   new operation. Historical UNKNOWN custody stays UNKNOWN.
5. Use actual stage evidence to propose targeted work. Before any full-Q admission,
   review the final implementation and evidence-based complete budget. Full Q must
   still accept exact probe32, then100, then384 with all required controls and
   unchanged final verification/cleanup. Any additional diagnostic tests need an
   explicit exact roster and separately reviewed bounded partition; they cannot
   displace those516 methods or be silently added to a count. Positive diagnostic
   observations are not a complete runtime-time guarantee.

The independent actual review of a future QD operation must bind original tool
chunks, native identities as exact integers, both full raw journals, complete
selected-stage/event joins, source/runtime pins/census, full final verification,
output accounting and all original owned cleanup. It records every unavailable
stage as such. No summarizer fills missing markers or replaces raw bytes with
digest-only evidence. Prefix acceptance cannot establish full-operation timing,
causal bottlenecks, complete dependency/ABI behavior, original package custody,
G2 or scientific eligibility. P remains disabled throughout.
