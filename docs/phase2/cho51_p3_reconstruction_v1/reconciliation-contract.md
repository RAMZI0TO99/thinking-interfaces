# Exhaustive ledger and non-authorizing outcomes

Reconciliation compares historical observations with fresh reconstructed evidence.
It does not erase debt. A positive match means the stated bytes/occurrence facts
match; it does not mean the historical source decision, custody or effect is safe.
This contract must be specialized into closed schemas and qualified source before
use. The term report below does not mean a resumable kernel checkpoint.

## Domain, identities and joins

There must be exactly one ledger entry per original resolver row: 18,793 for
this predecessor, ordered by the immutable historical row identity. Embedded
1,786 unresolved binding loads and3,972 effects remain complete in their owning
node payloads and receive explicit sub-obligation joins. They are not additional
distinct AST nodes. Require exact membership, uniqueness and counts, not just
equal totals. The 786 edges,1,782 frontiers and724 queues each retain their full
payload and original ordinal even where content is repeated.

The five-source inventory has a separate exhaustive 13,406-entry occurrence
ledger and an explicit cross-inventory intersection. Join by `(module, source
SHA256, AST field path)` and recompute content-derived IDs. Equal hashes alone,
source locations alone, or node kind alone cannot join occurrences. Compare
parent/child, kind, raw span/hash and algorithm-specific fields individually.
Inventory and resolver scope/analysis fields have different schemas; absence of
a field is not equality. Duplicate or inconsistent occurrence identities refuse
before semantic classification. Current-only occurrences receive their own
complete inventory; they cannot disappear because no historical row names them.

For this historical bundle, static tuple inspection found no shared occurrences.
That is not a fresh current-source reconstruction or a general promise of no
overlap. Recompute the joins in the future admitted producer. Do not sum source
observations as distinct without an actual tuple join.

Each entry requires the original identity and **complete original payload**,
an ordered list of current evidence identities and the complete evidence needed
to assess that relation, one outcome, and a machine-readable reason/witness.
References may locate payloads inside the same wholly retained and verified
bundle. A pointer, digest, count or unavailable historical file is not a payload
substitute. Copies count wherever the active contract says copies count; merely
interning a JSON object does not change the logical row/history denominator.

Permitted outcome categories (all preserve the original obligation):

| Outcome | Required meaning |
|---|---|
| `MATCHED_OBSERVATION` | Same source occurrence and explicitly compared fields; still no effect/capability disposition |
| `MULTIPLE_CANDIDATES_UNRESOLVED` | Complete bounded candidate set retained with why uniqueness is unproved |
| `SOURCE_DRIFT_UNRESOLVED` | Old and current pins/fields differ; both retained; never unchanged-source continuation |
| `MISSING_CURRENT_ORIGIN_UNRESOLVED` | Complete retained missing/ambiguous/native-origin evidence; no invented empty template |
| `ANCESTRY_UNRESOLVED` | Old immediate `via` cannot identify a unique root requester; no guessed ancestry |
| `SEMANTIC_UNRESOLVED` | Byte/site relation known but member/export/binding/effect/refusal semantics remain unproved |

Unverified input or cap/stop/writer failure is an operation refusal, not a seventh
way to claim that exhaustive reconciliation completed.

## Row-specific obligations

Origin rows compare content identity and full historical/fresh descriptors
separately. A new handle does not retrospectively prove old ownership/cleanup.
Nodes rejoin complete lexical, parent/scope and effect fields; unsupported syntax
stays explicit. Reconstructed exports and member candidates are retained even
if absent from the old serialized state, with current provenance and uncertainty.

Edges compare old source/target/site/phase/epoch/conditional values to every
matching current template and context. Missing old alias/kind information may
prevent a unique join. Template sharing cannot collapse old ordinals. Frontier
rows retain exact reasons, sites, candidates and contexts. In particular an old
`multi_phase_join_unresolved` record remains historical debt when new propagation
works; no status relabeling proves a source decision.

Queued rows have `(module, phase, via)` but no root requester. Rebuild current
facts from all36 admitted seeds and complete edge templates, retaining all
possible root requesters. A null `via` may join matching seed/prefix witnesses
only after full spec checks. A non-null `via` names an immediate site, not an
authenticated ancestry chain. If ambiguity or missing ancestors remains, emit
`ANCESTRY_UNRESOLVED` and preserve all bounded witnesses; never choose the first
seed, infer uniqueness from a single discovered path, or discard late contexts.

## Publication and claims

A complete reconciliation report, if it fits, binds exact old/current inputs,
all ledger payloads, current-only records, exact tuple intersection, counts,
limit accounting, live guard outcome and final input verification. It always has
G2/launch/capability/scientific flags false and identifies itself as non-resumable
unless a separately accepted checkpoint protocol is fully satisfied. No report
or classification alone is an effect-discharge mechanism.

Publication stages all pages under the unused operation's owned directory using
CreateNew, verifies their descriptors, then writes a committing index last. The
shared P allocation includes index, native descriptors, ledgers, snapshots,
histories, timing/control records and caller handoff. The committed index must
not precede the reviewed final-verification commit condition. If integration
uses an earlier draft index for final verification, that file is explicitly
provisional and cannot be interpreted as committed or accepted. Actual acceptance
still requires exact caller return, full original-handle verification and owned
cleanup reviewed independently of the source author/reviewer.

On capacity/input/stop/writer/verification failure, preserve the failed operation
and any partial artifacts as failure evidence. Emit a bounded refusal summary
only if the guarded failure/cleanup path can safely do so. It states which checks
completed and which did not, has no accepted checkpoint or exhaustive-report
claim, and is not a substitute for unmaterialized debt. The original complete
predecessor remains immutable. If even refusal publication fails, retain outer
return and closure evidence and leave disposition unresolved. No silent retry.
