# Retained inputs and deterministic reconstruction

This is a required producer design, not a runnable protocol or source acceptance.
Concrete successor filenames, closed wire schemas, exact source roster, Q cohort
partition and the reviewed output allocation must be frozen with implementation.
No implied defaults in this design may become silent implementation choices.

## Historical and current identities

The historical resolver input is the index and all 74 ordered pages from P2
operation `3d3e1c9b-2bf2-41b4-89c6-cbdda692a795`, plus its admitted plan spec,
source/runtime bindings and independent actual acceptance. The five-source
inventory contributes its index and all 53 pages from that same operation.
The [design input manifest](../../../runs/coordination/cho51_p3_reconstruction_design_20261101_v1/retained-inputs.json)
pins 136 files: the 129 index/page files and seven supporting source/evidence
files. It is a static review input, not the later execution coverage manifest.
The future admission must add every live source, runtime, historical admission,
descriptor and supporting dependency actually consumed; these 136 pins alone
are insufficient operational coverage.

At runtime a reviewed native reader must retain fresh handles for all input
files before use, verify regular local files, required sharing/link/reparse
predicates, exact sizes and hashes, and retain current native descriptors.
Check historical descriptors against their authentic index; separately record
fresh descriptors. Historical NTFS identities are evidence of the old operation,
not identities to invent, silently replace, or require to survive an authorized
file migration. A changed native identity with equal content is explicit new
custody, never continuation of a released handle. Ambiguity refuses.

Read each index under a closed schema; require false launch/G2 authority flags,
exact expected schema and counts. Read pages in descriptor order, not filesystem
enumeration order. Verify path, length, hash, family/schema, 256-row interior
pages and bounded final page. Detect duplicate JSON keys before interpretation;
reject unexpected keys, types, numbers, trailing material and path aliases.
Do not route FILETIME or other int64 identities through floating-point JSON.
Recompute full row/embedded counts and canonical frontier, queue, origin/spec
digests. Reordering or omission is an input failure, not unresolved semantics.

Original row identity is `(index SHA256, page ordinal, page SHA256, row ordinal,
row kind, canonical row SHA256)`. Global ordinal is derived from page order.
Two equal payloads at different ordinals remain two historical obligations.
Native descriptors and content pins are different identities.

Bind reconstruction to a fresh algorithm version, exact source/runtime pins,
current spec, ordered roots and seed set, predecessor input bundle, and candidate
migration evidence. Compare old and current binding components individually.
Any changed source, spec, roots, algorithm or runtime forbids an unchanged-binding
continuation claim. New producer algorithms necessarily create a **fresh
reconstruction with reconciliation**. They do not rebase an old checkpoint.
Record drift per component even when an observed source occurrence is equal.

## Fixed roots and phase/requester semantics

The historical LP10 spec has exactly 36 ordered seeds. Preserve that exact list
and its phase assignment: first14 L2, middle20 L3, final2 L4. Roots are retained
Python `Lib`, project `.venv/Lib/site-packages`, then project root, in that order.
Suffixes are `.cp312-win_amd64.pyd` and `.pyd`; builtin/frozen tables are empty.
The fresh admitted counterpart must match or explicitly report a new spec; no
environment probing, `sys.path` inference or candidate import supplies a default.
Generate each seed's exact ordered package prefixes. The root requester remains
the seed identity through every conservative propagation edge.

For each selected name, resolve against the fresh physical map using the ordered
root/package rules. Retain all ambiguous candidates and missing-parent reasons.
Only an unambiguous source module/package receives a source template. Native,
builtin/frozen, ambiguous, namespace-unknown and missing origins retain complete
origin obligations and blocked work; never fabricate a source hash or a zero-edge
template to mark them complete. An admitted absence is an observation, not proof
of universal import behavior. Source and native search/ABI decisions stay separate.

Read exact bytes through the retained reader, verify the content pin, and parse
only under the reviewed temporary AST-only allowance. It binds exact path and
bytes, admits only the intended parser event, and is removed on success, syntax
refusal, guard failure and every exception. No input import, execution, bytecode,
module initialization, native loading, networking or numerical work is allowed.
The active guard is sampled during input reads, parsing boundaries, traversals,
joins, replay, encoding, writes and final verification; pre-supplied booleans
never replace live stop/time/resource checks.

## Complete module transaction

Build a module in private bounded staging. Retain source origin, every AST field
path and parent/scope join, source span/hash, lexical candidates and unresolved
binding/effect payload, full export analysis, pending members, edge alternatives,
unsupported constructs and diagnostics. Exports use tagged states: unknown with
reason, or observed literal names with their exact source witness. An empty
observed list is different from unknown. Literal names are not runtime attribute
or star-import certificates. The old resolver's discarded exports/pending members
must be reconstructed; its queue cannot restore them.

Commit a complete module only if every limit and publication precondition fits.
On refusal retain the prior committed state and the unconsumed obligation in the
operation's failure evidence. Never publish a partial module as complete. No
checkpoint exists unless *all* required payloads and pending work are present.
Selection order and bounded unresolved remainder must be explicit; discovering
more input than fits refuses instead of trimming a queue or restarting counters.

Produce edge templates from exact import/alias and package-prefix sites, with
source, target, site, alias/prefix ordinal, eager/deferred epoch, conditional flag
and a reviewed kind (`import`, `from_base`, `member_candidate`, `package_prefix`).
Attribute/submodule alternatives remain alternatives, not resolved imports.
Historical edges lack kind/alias ordinal and may have equal payloads; map each
old ordinal to zero, one or multiple explicitly witnessed candidates. An
ambiguous join stays unresolved. Deduplicating a propagation template never
deduplicates the historical records or removes multiplicity from the ledger.

Facts remain `(module, phase, root_requester)` and links retain immediate edge
provenance. Conditional/deferred edges are conservative may-reach facts. Late
phases/requesters traverse cached templates rather than disappearing at a global
`seen[module]` check. Cycles terminate on finite facts/links, not full paths.
No phase fact proves runtime reachability, order, a safe effect or a host capability.
