# Cho source-selection evidence storage review

23 September 2026. This is a read-only sizing estimate for the proposed
four-method, five-shot Cho2017 tranche. No selector fit, scientific cell,
checkpoint, compute admission or change to the evidence format resulted from
it. The scope and candidate settings remain unratified.

## Current inline evidence format

`evaluation/phase2_selection_evidence_binding.py` requires each source fit to
carry an `input_identities` map for all permitted source subjects. For a
52-subject target case, the proposed two-candidate selector has 51 validation
folds per candidate, each fit trained on 50 subjects, followed by one final
fit on 51 subjects for the winner. This makes
`2 × 51 × 50 + 51 = 5,151` inline identity copies **per target, seed and
method**, before step histories or validation bindings. The present
`SelectedSourceStore` writes complete canonical JSON evidence without
compression; repeated bindings therefore occupy separate bytes in every
record.

A read-only calculation used the existing 52 audited Cho episode catalogs,
current 60 Hz artifact trial metadata and the `ChoProfileBinding60Hz` record
shape. Its [write-once probe receipt](../../runs/phase2/freeze_readiness/20260923_evidence_size_probe/receipt.json)
has envelope SHA-256
`a2c4aca3469d88f677ddc24ef05b1500118393e3bce68ee2e71d2223a0f3f37d`
and file SHA-256
`ce5522fdb10c5e7d7af0a9ba91fb1dd04f7eea696c8994b118c03925d009853a`.
The adjacent [probe](../../runs/phase2/freeze_readiness/20260923_evidence_size_probe/probe_evidence_size.py)
reconstructs all 52 five-shot binding hashes and checks them against the
historical cohort audit. It reads current 60 Hz NPZ trial metadata without
decoding signals; it does not fully rehash all 52 NPZ or raw files. One
subject's reconstructed source identity was cross-checked against
the real 60 Hz loader: subject 03 was exactly **6,645 bytes** in canonical
JSON. Across subjects, the reconstructed identities ranged from **6,509 to
7,605 bytes**, with a mean of **6,695.46 bytes**. The target 01 complete
selection's source maps total **34,565,636 bytes**: its first fold has a
335,599-byte 50-subject map and its final 51-subject map is 342,234 bytes.
The calculation used fixed-length stand-ins for already audited B artifact
digests when it avoided a fresh 52-subject hash pass; that affects neither
canonical string lengths nor the copy-count arithmetic. This estimates the
current inline schema, not actual evidence generated by a fit.

Together, those JSON **values alone** project to **27,906,236,120 bytes
(25.990 GiB)** before keys, punctuation, step histories and other records.

The map projection sums subject-specific canonical byte lengths over all 52
target choices and five seeds. The EEGNet identity map is much smaller because
it binds Profile A digests without the full 60 Hz episode binding. The
validation-binding row is additional. Step rows, other evidence fields,
manifests, intermediate checkpoints and filesystem overhead remain unpriced.
As a structural cross-check, an existing bounded BCI LaBraM evidence file's
first seven-subject fold is 138,542 bytes, of which 120,141 bytes are source
identities, 15,045 bytes a validation binding and 1,705 bytes step rows. The
Cho projection is not obtained by scaling this different dataset's trial
count.

The [actual-model weight probe](cho_selected_source_storage_review_20260923.md)
projects **18,176,500,160 bytes (16.928 GiB)** of distinct final weights. The
current inline identity maps plus those weights are therefore **42.479 GiB**,
before the other evidence listed above. At the write-once probe's D: snapshot,
**28.635 GiB** was free. Preserving the unchanged **20 GiB** project floor left
**8.635 GiB** usable: the weights-plus-maps projection exceeded that headroom
by **33.845 GiB**. The JSON values including validation bindings alone exceed
headroom by **17.355 GiB**. Adding those validation bindings to the final
weights raises this still-incomplete storage floor to **42.918 GiB**. At the
same disk snapshot, at least **62.918 GiB** free at the start would be needed
to hold only these values while preserving the 20 GiB floor, **34.283 GiB**
more than was free. Even the separately proposed, unimplemented sparse-weight
option (5.648 GiB of weights) plus current inline maps would project to
31.199 GiB, exceeding that snapshot's headroom by 22.564 GiB. All free-space
numbers are snapshots; a new admission measurement is required for later work.

A synthetic target-01 JSON array of 102 inner-fold maps plus its final map
was **34,565,740 bytes** in memory and **1,746,333 bytes** with gzip level 6
(5.05%). This array framing differs from a prior exploratory object-framed
example, while the full-tranche analytical map totals above agree exactly.
Compression or shared binding references could materially reduce
physical evidence storage, but neither is implemented or accepted by the
current store and verifier. This observation grants **no storage credit** and
does not address full weights, step histories, checkpoint retention, runtime,
the 5,253-step requirement above the 256-step engineering cap, or the
unratified scientific freeze. Any format change needs an exact verifier and
restore-path review before it can enter the execution plan. A
[versioned format option](cho_evidence_storage_format_option_20260923.md)
sets out that review and migration boundary.
