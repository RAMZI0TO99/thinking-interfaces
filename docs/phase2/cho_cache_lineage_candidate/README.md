# Cho local reconstruction candidate

This separate data engineering candidate compares existing Profile A caches
with the current installed Cho conversion and frozen project preprocessing.
It overrides only the dataset's file resolver to use a pinned local MAT file.
It inherits demeaning, microvolt conversion, the 500-sample zero buffer and
class stacking, then applies the default zero-offset annotations and frozen
unified Profile A. The converter's class-block order does not authenticate
the original acquisition chronology.

The five-check synthetic probe must run in a fresh guarded attempt and have
a complete reviewed result with physical Job release. Only then may subject
001 be separately admitted. A separately admitted remaining51-subject batch
may follow a complete reviewed subject001 comparison and measured resource
envelope. Prepared code, compilation and static input maps are not passing
runtime qualification. No stage is activated merely by this candidate.

The copied `worker_common_004.py` is the separately qualified immutable data
helper. Its legacy result schema name contains MMIDB; Cho stage, protocol,
operation and input bindings define this candidate's scope. All raw/cache
hashes are checked before and after; only receipts and owned synthetic files
are written. Existing data, caches and weights remain intact. Differences
are reported using the existing1e-12V absolute/1e-6 relative tolerance and
exact metadata checks; no processing or tolerance is adjusted to force a match.

No model, checkpoint, fitting, recorder, scientific eligibility, gate signature,
experiment freeze or additional original LaBraM case is admitted. Every stage
needs its own finite current-source/runtime/input admission, coordination and
unchanged resource floors. All52 subjects are comparison targets; this does
not decide scientific inclusion or exclusion.
