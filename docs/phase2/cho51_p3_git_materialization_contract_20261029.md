# R1 isolated Git materialization contract

29 October 2026. This is a separate runtime provisioning operation, neither Q
qualification nor file-only P observation. It requires independent source review,
Root's exact scoped adoption, fresh admission and a different actual reviewer.
It preserves the consumed P attempt and all frozen sources, pins and receipts.

## Reason and scope

P operation e0d2815a-9c58-4ec8-b897-81f3f861d149 refused a regular single-link
predicate before publishing a map. Independent actual review supports its owned
lifecycle closure, not successful preparation. Subsequent static metadata found
174 selected hard-linked files, all within the installed Git distribution. The
exact first failing path was not recorded. P's single-link guard remains intact.

R copies the exact 243 proposed Git inputs (189,434,327 bytes) as opaque payloads
into a fresh project-owned directory. It does not modify the installed Git,
execute Git or copied code, compile source, import packages, run tests, read
scientific data or weights, contact the network, or spawn a child process.
Source hardlinks are permitted only for this bounded copy input. Original
read-only source handles deny writes/deletion and remain retained through
copying and closeout. Their exact pinned bytes must be verified before copying.
This is not a hardlink exception in P's retained reader.

The admission binds every canonical source/relative path, byte count and digest.
Sources must be regular non-reparse files under the declared installed Git root
with ordinary ancestry. Case aliases, path traversal, unexpected roots and
unlisted files refuse. Distinct admitted source names can identify the same
hard-linked source; their destination files must have distinct identities.

## Ownership, limits and publication

Limits are 90 seconds whole,60 work,5 cleanup, a65-second original-process hard
deadline,512 MiB caller private memory,4 GiB startup/active available RAM and
20 GiB free disk. The original UTC/QPC, direct cached Process handle, independent
PDH guard, local stop file and deadline cover startup, pinning, PE loading,
copying, readback, publication and final closure. No deadline is reset.

The exact previously Q-qualified P native PE may be loaded from retained bytes
only for native file identity and an empty Job limit/closure probe. It cannot
create a child here. That empty Job does not contain the caller; the independent
512 MiB guard and original-process self deadline bound the caller. No native
source compilation occurs during R.

The binary payload allowance is256 files,16,777,216 bytes per file and201,326,592
bytes total (192 MiB), enforced before allocation and throughout copying. Read,
hash and copy chunks are at most65,536 bytes. Separate metadata is at most1 MiB
per file and8 MiB total, and bounded stdout/stderr remain1 MiB each. These are
explicit R provisioning bounds; Q and P output/fixture limits do not change.

The admission fixes destination_parent to D:/Aenv/pro3/runs/local_runtimes and
destination_prefix to git_<operation UUID>_. Set TMP/TEMP for this process only,
verify the effective temporary parent, then use .NET's atomic unique-directory

prefix and root. No check-then-create fallback is allowed. Restore the process
environment during cleanup. All destination files use create-new original
read/write handles sharing read only; no overwrite, rename or deletion occurs.

Preserve the exact relative topology. Original output handles remain live for
flush, full hash readback, native identity comparisons and ordinary/single-link
checks. Each output identity must differ from its source, remain stable and be
unique among outputs. While original handles deny rename/deletion, path metadata
checks must report regular non-reparse single-link outputs. Final complete file
and directory census must equal the owned topology. The seal binds exact native
identities, paths, sizes and hashes; actual acceptance occurs only after tool
return and independent review resolve original handle and guard closure.

Stop, guard, time, input, publication or cleanup failure consumes the attempt.
Close every original handle and join the guard under the original cleanup bound.
Preserve partial files and diagnostics as ineligible; never overwrite, remove
unrelated paths, retry automatically or mark partial provisioning accepted.
