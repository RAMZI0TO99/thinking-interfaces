# P1 retained preparation engine and scoped Q qualification

29 October2026. Implementation-specific supplement for engineering review.
This document is not an admission or a dependency-completeness assertion.

The [local validation contract](cho51_p3_local_validation_contract_20261029.md)
requires Q qualification of new mechanisms before a separately admitted P
operation. Accepted [Q4](cho51_p3_q_qualification_20261029.md) supplies retained
read/identity and supervision primitives, not a complete physical dependency map.
This step implements and qualifies the layer joining a reviewed physical recipe
to native retained observations. Actual package/runtime preparation remains a
distinct P operation after its physical recipe and caller have been reviewed.

## Exact implementation

New [P1 sources](../../tools/local_validation/p1/README.md) define a closed recipe
with explicit roots, roles, file/tree groups, literal suffixes, exclusions and
an exact expected path/bytes/SHA256 map. All four source/runtime/package/metadata
roles are required. Seeds must be members of the expected physical map. An
unselected directory entry remains part of the bounded tree census; excluded
directory contents are expressly outside that recipe. Exact-file groups make
no claim about unrelated parent-directory members.

The engine checks the selected expansion before reading selected bytes, retains
native handles, compares initial/final membership and identity, verifies hashes
and bounds, and returns a defensive proposed-map record. It composes unchanged
v1 supplied-data primitives and the exact Q4 retained reader. The caller must
keep its session through publication and verify before and after publication.
Failure poisons the session; final closure remains the caller's obligation.
No freshness claim survives handle release.

The25,000-file,4GiB-total,2GiB-file,depth32 and64KiB-chunk constraints remain;
8MiB/200,000-node JSON bounds may refuse a smaller map. A recipe does not infer
transitive dependencies or confer coverage, loader, runtime, launch or scientific
authority. Candidate/package imports, data/weight access and compilation are
absent from this engine. An actual physical recipe must separately trace the
dependency plan, live source census, metadata/resources, runtime and Git inputs
and be reviewed for scientific-data exclusions before any actual P observation.

## Q successor and retained limits

The new [P1Q runner](../../tools/local_validation/p1q/README.md) adapts Q4 without
editing or replaying it. It changes only the phase/module/source-review bindings,
adds the P1 engine and tests, loads the frozen Q4 reader under its own namespace,
and binds Q4's accepted qualification as predecessor. Its expected suite is108
methods (31 foundation,30 reader,12 protocol,35 P1); separate eight timestamp
and two native fault controls retain their Q4 purposes. Source counts are not
results. A later changed suite requires a new exact source/roster review.

Q limits remain90s whole,60s work,5s cleanup,512MiB process/caller and768MiB Job,
4GiB startup/active RAM,20GiB disk,one library thread and hidden GPUs. Root plus
one author/reviewer remains the collaboration limit. Startup sampling, clocks,
local stop, independent deadlines, original process/Job/pipe/file ownership,
same-byte execution, output bounds and actual external return stay mandatory.
The caller's in-memory compiler is an admitted Q effect only, never a P claim.

P1Q must receive independent source review, implementation-specific adoption
binding this supplement, a fresh UUID/runtime/source admission, and separate
actual-result review followed by Root acceptance. No old admission is reused.
The scoped policy replacement applies only to this exact adopted Q successor;
it does not admit an actual P operation or satisfy historical custody.

## Evidence boundaries and next gate

The qualification fixtures are tiny JSON files in a fresh owned attempt. Their
roles are synthetic labels, not observed third-party packages. Real hardlink,
writer and retained-tree behaviors are distinguished from injected reparse
attributes. The full26 qualification scenarios and original48-case custody
matrix remain incomplete. No117 candidate case or34 successor control runs.

Q1 stays FAILED_CONSUMED_CUSTODY_UNKNOWN; Q2/Q3 consumed failures and Q4 accepted
scope remain frozen. Bootstrap004 stays consumed,005 held,006 unadmitted and
historical custody UNRESOLVED. No restart,complete-dependency or scientific
authority is inferred. Scientific cells remain0/1020 and final freeze unsigned.

After accepted engine qualification, the next gate is a concrete physical
dependency recipe and a reviewed file-only P caller. Actual P then requires
fresh admission, native retained observation, independent pin/coverage and
actual-result review, and Root adoption. L/V/C remain separate later stages.
