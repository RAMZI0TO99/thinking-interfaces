# HB1 bounded qualification approach

Design only. No runner, native integration, provider service or test is executed
or admitted. Preserve frozen SC1 and the LP19/LQ19/lplan16 refusal entry points.
The finite plan below has prerequisite gates; listing a unit is not permission
to run it. Missing provider/lifecycle/capture evidence blocks runtime readiness.

## Evidence order and noncircular claims

1. Implement and independently review only the bounded supplied-frame verifier,
   unavailable-provider refusal and exact discovery-partition checks in new
   sources. Freeze exact new method IDs/source/runtime closure before any run.
2. A separately reviewed/admitted component harness may later exercise supplied
   messages, fake provider replies and controlled failure models. Such evidence
   establishes verifier behavior only. It cannot authenticate the provider or
   bootstrap a positive provider claim, native custody or full Q.
3. Independently establish the real provider's original identity/delegation,
   durable atomicity across sessions/restart, complete governed attribution,
   native cancellation/closure, loaded-code/runtime binding and exact accounting.
   Static/provider documents and fake replies alone are insufficient. Any actual
   project onboarding probes require their own reviewed finite command/output
   contract, fresh admission and separate actual reviewer under existing guards.
4. Resolve the original-clock metadata/review lifecycle and complete capture
   bounds. Qualify real component/native scenarios with the independent original
   observer and complete artifacts. A result produced solely by the component
   under test cannot certify its own provenance, census or cleanup.
5. Reassess complete changed-Q stage costs and output feasibility. Only then may
   a newly reviewed complete-Q successor receive separate probe32, mechanisms100
   and inherited384 admissions in that order, each with all controls and closure.

These are evidence dependencies, not pre-admitted runtime stages or authority
to use legacy launchers. The independent local platform/observer plus original
provider provenance is the stated trust root; the system does not recursively
declare its own JSON to be that root. If no qualified independent observer or
provider can supply the necessary evidence within the accounting/lifecycle
contract, stop at the accepted source/model scope and report unavailable.

## Finite component-unit proposal

Two types of future units are specified; neither is currently implemented or
admissible. Each uses one original caller clock, fresh unused identity, exact
pins, owned containment, full final verification and a different actual reviewer.

**VFY unit:** execute the exact qd10 + SC54 existing supplied-model methods plus
the exact newly implemented HB verifier/runner methods, after full discovery.
Its claim is component model behavior only. Future additions require an explicit
finite roster and worst-case report bound before source acceptance/admission.
No native/provider positive behavior is inferred from those64 existing methods.

**NATIVE units:** at most one complete predeclared native HB or SC scenario per
new component operation, with all controls necessary for that scenario and
complete cleanup inside that operation. The finite scenario sets are HB24 and
the still-open SC40; preserve all36 diagnostic obligations separately. A scenario
needing several linked subcases must finish all of them in the same unit; if its
source-derived bounds cannot fit, it is unadmitted, not split into accepted tails.
Model-only HB scenarios do not need fictional native runs. Runtime scenarios
must be selected by exact ID and complete expected evidence, not discovered
through an unbounded loop or retried automatically.

A component result records scenario ID, complete source/runtime/provider/caller
identity, started/completed subcases, fresh clock/resource evidence, every owned
artifact/process/handle, final verification and actual return. Its possible
positive status is COMPONENT_ONLY, never Q_QUALIFIED/P_ADMITTED or scientific
acceptance. The full qualification matrix still requires all applicable native
obligations; many independent component passes cannot be added up to full Q.

All component units retain Q's whole90/work60/cleanup5/hard65/child55 ceilings,

Use absolute minimum deadlines from the original caller origin and remaining
stage/final-verification budgets, never a fresh per-control clock. Actual native
deadline/resource failures are failures; only a specifically admitted intentional
stall control may have its expected bounded timeout. QD45/53/55 remain QD-only.

## Capture and failure-path prerequisite

Keep full original tool chunks, native integer text, escaping and every envelope
and stderr/failure path. Existing raw_tool_return capacity is1,048,576 encoded
bytes and external_return65,536. A raw1MiB runtime ceiling is not a capture proof:
one permitted1,048,576-byte ASCII control-character text can require6,291,456
JSON string bytes before headers, more than the raw slot. Even1MiB printable
content has no room for a positive envelope. The condition that any stream up
to its hard cap is capturable is therefore false for the unchanged representation.

This does not prove every finite Q operation's output is too large. A reviewed
finite producer grammar and actual tool transport must establish a tighter
complete maximum for all success/failure paths without changing stream guards
or truncating raw evidence. Include dynamic exception text, startup/native tool
errors, cancellations, multiple tool chunks, framing and report expansion. A
claimed constant or successful example is insufficient. Otherwise refuse
admission; a representation/allocation successor needs its own review within
unchanged guards. The same requirement applies to component units and provider
onboarding; the design does not exempt them to break a dependency cycle.

If an unexpected overflow occurs, keep the consumed charges/partial evidence,
perform bounded owned cleanup and report refusal/unknowns in the original trace.
Do not export the overflow to documentation, another directory or a17th file.

All original resolver/custody/G2/117/V34/scientific obligations remain. Nothing
here discharges original-package-path custody or accepts a real scientific case.
