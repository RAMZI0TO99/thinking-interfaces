# Adopted 51-target selector-record collection

`collection.py` is a separately versioned read-only bridge. It consumes the
qualified publication collection, all 1,020 detached tensor requests and
independent native receipt pins. It preserves subjects02–52 as evaluation
targets and all52 subjects as source/inner-validation inputs.

The full collector calls the native tensor-receipt collector before and after
the selector loop and compares the exact immutable results. It independently
pins the direct `configs/phase2/selection_ceiling.toml` file to the adopted
integer5,253 policy and retains physical manifest/evidence/weights witnesses
around the final receipt recheck. It snapshots external request and pin
sequences before its first dependency call.

For each case, the unchanged manifest-file verifier binds external publication,
source, recipe, model-state and weights hashes. `SelectedSourceStore` resolves
bounded canonical or factored evidence through the pinned manifest. The method
template derived from the recorded candidates must match the independent
request and adopted method digests. The unchanged **public**
`evaluation.phase2_selection_evidence_binding.verify_cho_selection_evidence`
checks the complete recorded folds, RNG/batch/loss/count declarations, exact
rational winner and complete declared selector budget. The bridge never calls
the private structure-only verifier as a substitute.

Successful full production collection exposes
`full_selector_record_consistency_verified=True`. It preserves explicit false
properties for historical selector training, broader selector admission,
paired analysis, combined selection/publication/tensor admission and scientific
results. Complete records do not establish that their historical gradient work
occurred. The collector launches no process, creates no recorder/attempt,
loads no input arrays and performs no fitting or predictions. Stable rereads
detect observed drift and do not create a filesystem lock.

`_verify_selector_case(project_root, route, request, *, expected_source)` returns
one immutable claim and physical manifest witness. A direct helper invocation
does not authenticate native tensor execution or a complete 1,020-case roster.
It is exposed only as a private focused integration-test seam.

`test_collection.py` contains prepared synthetic boundary tests. They fabricate
the full metadata roster and mock native receipt admission, file/store reads,
method derivation and the public selector verifier; they cannot qualify actual
study inputs, selectors or tensor executions. Root-owned guarded integration
tests must exercise complete fabricated records through the actual public
verifier. No checks were executed by the source-authoring worker. Preserve all
canonical and previously qualified sources and evidence.
