# Reconstruction, admission and staged acceptance

The frozen LP10/LQ10/lplan7 sources, Q2/P2 receipts and all earlier failures stay
unchanged. No archived launcher or spent attempt is reused. This design changes
no execution-policy bytes or scientific decisions.

## First implementation: supplied-state kernel and Q

Root owns integration/admission/docs; one named worker may own the new kernel
and its tests. A different reviewer accepts source. A separate actual reviewer
examines saved Q results. Root plus one peer is the maximum active team.

The new kernel is not wired into P. Its exact interfaces and closed schemas are
documented with implementation source and independently reviewed before freeze.
Small supplied fixtures exercise the qualification scenarios without importing
candidate code or installed numerical libraries. Discovery retains all 384
inherited and 40 resolver methods and adds an explicit finite kernel cohort;
each operation stays at or below 384 methods. Every cohort runs the eight UTC,
two native faults, three sharing, five observer and two bootstrap controls.
Three disjoint rosters and all actual reviews are required for any aggregate.
If a two-cohort partition combines the existing 40 and new kernel methods, that
exact partition and control execution must be reviewed and bound explicitly;
no inherited method may disappear. No historical qualification certifies the
changed source. Q's P-bootstrap cases still do not exercise P's aggregate branch.

Common sources remain at most256; source consolidation may replace predecessor
paths only with semantically accounted successor counterparts, never omit live
dependencies. Runtime pins and unused attempt identities are fresh. Q keeps
90 seconds whole,60 work,5 cleanup,65 hard,512/768 MiB process/Job; RAM startup
and active4 GiB, disk20 GiB, one thread, hidden GPUs, local PROJECT_STOP.json,
original process/Job ownership, bounded streams and final verification unchanged.
Unavailable resources or remaining-time failure refuse; no silent retry.

Acceptance is only for supplied-data mechanisms. File/text/hash/schema inspection
is static review, not an executed test. Candidate117, V34 and science remain zero.

## Later integration: reconstructed real-source state and file-only P

An independently reviewed producer must first read the historical index and all
74 pages through fresh retained handles, verifying ordered descriptor/content
joins and exact row accounting. Preserve the original 15,501 module rows,786
edges,1,782 frontiers and724 queues; binding/effect payloads inside nodes count
as obligations too. Their old digest/row ordinal/kind is a migration identity.
The old records are immutable historical inputs, not a current physical census.

Reconstruct the 36 seeds and package prefixes from the exact admitted spec,
ordered roots, source/runtime pins and retained bytes. Parse each selected module
under the scoped AST-only allowance. Retain complete exports/pending-member,
origin, lexical/effect and edge-template state. Join every old occurrence by
module/source SHA/AST field path and every frontier/queue by its original record.
Emit an exhaustive one-to-one old-record accounting ledger: preserved historical
obligation plus corresponding reconstructed facts or explicit unresolved reason.
Never relabel a stale multi-phase refusal as a proved source decision. Old queue
contexts whose missing ancestors cannot be reconstructed remain unresolved.

Reject source/spec/root/algorithm/runtime drift as a continuation. A fresh root
reconstruction with a separate old-to-new reconciliation may observe changes,
but must not claim an unchanged-source continuation or silently discharge old
debts. Raw predecessor records and complete current obligations must remain
available; source identity and native descriptor identity remain separate.

Before admission, review the complete shared output allocation, source/extras
coverage and exact producer/consumer schemas. P2 used198 files/46,810,857 bytes
and208.85 seconds including final verification; this is evidence of limited
remaining capacity, not a budget for automatic replay. P remains300 seconds
whole,240 work,5 cleanup,245 hard,4096/5120 MiB process/Job,256 extras and the
unchanged shared output/storage limits. AST-only parsing is permitted; candidate
imports, bytecode compilation, native dependency loading and numerical work are
forbidden. Full original-handle verification, census and owned closure remain.

Fresh Q, current coverage review and separate P admission precede each operation.
No reuse of P2's released custody or census. A producer that cannot materialize
all obligations within the existing limits must refuse before index publication.
Source review and actual P review are different acceptance claims.

Only later complete source decisions, implemented and qualified matching host
capabilities, and independent complete-plan acceptance can precede L. Propagated
phases are conservative static facts, never runtime permission. L/V/C remain
separately admitted stages; no commit/push or scientific execution is authorized
by this package.
